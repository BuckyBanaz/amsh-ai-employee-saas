## Backend (new, 2026-09-09)
- **First real backend for Amsh, built from scratch** in `backend/` (repo root), per `DOCS/AI_Receptionist_Project_Structure_Spec.md` and `DOCS/05_AMSh_Backend_API_Endpoints.md`. Explicitly separate from the user's older, unrelated `AI Clinic Receptionist` project (`C:\Users\Parikshit\Desktop\workspace\AI Clinic Receptionist`) — that one is being left alone.
- **Stack:** FastAPI + SQLAlchemy 2.0 + Postgres 16 + Redis 7, Dockerized via root `docker-compose.yml` + `infrastructure/docker/api.Dockerfile`. Ports intentionally non-default (Postgres 5434, Redis 6380, API 8010) to avoid colliding with the old project's still-running containers.
- **Working now, verified with real curl round-trips (not just written):** `POST/GET /api/auth/*` (register/login/me, JWT + bcrypt) and `POST/GET/PATCH /api/businesses*`. Data persists in real Postgres.
- Full spec directory skeleton scaffolded (`realtime/`, `engine/`, `speech/`, `llm/`, `rag/`, `memory/`, `tools/`, `verticals/`, `integrations/`, `billing/`, `analytics/`, `workers/`) — packages exist, no logic yet.
- DB models: Business, User, Agent, Call, Message, Transaction, KnowledgeDocument, Integration, Usage.
- **Not done yet:** everything voice/call related (needs real Twilio/Groq/Deepgram/ElevenLabs credentials from the user), and neither frontend is wired to this backend yet — both still run on hardcoded mock data.
- Two real bugs hit and fixed during setup: `pydantic[email]` extra wasn't declared (needed for `EmailStr`), and `passlib[bcrypt]` pulled bcrypt 5.x which is incompatible with passlib 1.7.4's backend-detection code (pinned `bcrypt==4.0.1` instead).
- **Team invite flow added** (`backend/api/routes/users.py`): owner/admin invites a teammate (admin/manager/doctor/receptionist role) → `POST /api/businesses/{id}/users` creates an inactive user + returns a 7-day invite token (no email provider configured yet, so the token is returned directly rather than emailed) → invitee calls `POST /api/auth/accept-invite` to set their password and auto-login. `GET /api/businesses/{id}/users` lists the roster. Full flow + all permission edge cases (can't log in pre-accept, can't double-accept, non-owner/admin can't invite, can't invite as "owner") curl-tested and passing.
- Swagger UI live at `/docs` (and ReDoc at `/redoc`), root `/` redirects there.
- `.env`/`.env.example` set up with per-provider comments (Twilio, Groq, Deepgram, ElevenLabs, Cartesia) for the user to fill in real keys.
